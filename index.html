03 / Reference

Security Documentation

1. Zero-Leak Execution Model

All operations occur strictly within transient JavaScript heap memory inside the local web browser. The codebase contains zero calls to fetch(), XMLHttpRequest, WebSocket, EventSource, or navigator.sendBeacon(). Zero analytics trackers or external CDN runtime scripts exist.

2. Deterministic Validation Engine

  • Credit Cards: 13–19 digit candidate extraction with strict ISO/IEC 7812-1 modulus 10 Luhn checksum validation. Rejects corrupted numbers, 12-digit and 20-digit strings, and embedded IDs.
  • Indian PAN: [A-Z]{5}[0-9]{4}[A-Z] validation with strict left and right word boundary isolation.
  • IPv4 Addresses: Exactly 4 octets, each in [0, 255]. Rejects negative octets and software version strings.
  • Indian Aadhaar: 12-digit candidate validation with Dihedral Group D5 Verhoeff checksum algorithm.
  • Indian Mobile: 10-digit mobile detection starting with 6–9 with prefix normalization (+91, 0), rejecting dates and timestamps.
  • International Phone: E.164 boundary constraints [8, 15] digits.
  • Email: RFC 5322 syntax validation with automatic trailing sentence punctuation trimming.

3. RFC-4180 CSV Engine & Injection Defense

KAVACH features a state-machine CSV parser that natively supports quoted commas, escaped double quotes (""), and embedded multiline strings. It enforces an explicit CSV formula injection shield, prepending ' to any cell beginning with =, +, -, @, \t, \r.

4. Deterministic Overlap Resolution

Candidate spans are sorted by start ascending, length descending, and deterministic priority tie-breaking. Half-open intervals [start, end) guarantee that no character is ever double-redacted.
