🛡️ KAVACH Engineering & Privacy Architecture

KAVACH is a zero-leak, 100% client-side privacy engine designed to eliminate PII leakage before data touches downstream systems.

1. Zero-Leak Execution Model

All sensitive operations occur strictly within JavaScript heap memory in the user's browser. KAVACH contains zero external network calls, zero tracking pixels, zero analytics, zero cookies, zero service-worker syncs, and zero database connectors.

2. Deterministic Validation Engine

  • Credit Cards: Strict 13–19 digit candidate extraction with ISO/IEC 7812-1 modulus 10 Luhn checksum validation. Rejects corrupted digits, 12-digit, and 20-digit strings.
  • Indian PAN: [A-Z]{5}[0-9]{4}[A-Z] structure validation with strict left and right word boundary enforcement.
  • IPv4 Addresses: Exactly 4 octets, each between 0 and 255. Strict rejection of software version strings (e.g. v1.2.3.4, release-2.3.4.5).
  • Indian Aadhaar: 12-digit candidate validation with Dihedral Group D5 Verhoeff checksum algorithm.
  • Indian Mobile: 10-digit numbers starting with 6, 7, 8, 9 with prefix normalization (+91, 0). Distinguishes phone numbers from dates and timestamps.
  • Email: RFC 5322-compliant syntax validation with automatic trailing punctuation trimming.

3. RFC-4180 CSV Engine & Injection Defense

KAVACH implements a native state-machine CSV parser that natively supports quoted commas, escaped double quotes, and embedded multiline strings. It also implements an explicit CSV formula injection shield, prepending ' to any cell starting with =, +, -, @.

4. Deterministic Overlap Resolution

Candidates are sorted by start ascending, length descending, and priority tie-breaker. Half-open intervals [start, end) guarantee that no source character is redacted twice.
